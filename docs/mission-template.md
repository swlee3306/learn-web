# /learn 미션 템플릿 + 검수 체크리스트 (초보/1일 1시간 기준)

목표: **미션 100개를 빠르게, 일관되게** 만들기 위한 고정 포맷.
- 대상: 완전 초보(비전공자)
- 1회 학습 시간: 30~60분 (하루 1시간 기준)
- 원칙: "설명은 짧게, 실패 피드백은 구체적으로, 성공 경험은 크게"

## 2) 미션 페이지 구성(권장 섹션)
### A. 오늘의 목표 (1~2줄)
- 사용자가 **이번 미션 끝나면 할 수 있는 것**만 적기.

### B. 준비물/규칙 (최대 3줄)
- 예: "코드 수정 후 Run 누르기", "힌트는 막힐 때만".

### C. 문제(해야 할 일) — 체크박스 3~6개
- 예)
  - [ ] 버튼을 클릭하면 카운터가 +1 된다
  - [ ] 10이 되면 '완료!' 문구가 나온다

### D. 힌트 (3단계)
- 힌트1: 방향만
- 힌트2: 핵심 코드 조각(한 줄)
- 힌트3: 거의 정답에 가까운 스캐폴딩(사용자가 마지막 10% 채우게)

### E. 자주 하는 실수 (2~4개)
- 예: querySelector 오타, 이벤트 리스너 대상/타입 실수, 문자열/숫자 타입 문제

### F. 통과 조건(테스트가 보는 것)
- 자연어로 2~4줄 (사용자가 "왜 FAIL인지" 이해할 수 있게)

### G. 성공하면 보상(한 줄)
- 예: "오늘 너 DOM 조작 한 번 끝냈다"

---

## 3) 채점/테스트 설계 가이드
- **검증은 UI 기준**으로(텍스트/DOM 상태/클릭 결과) 하고, 구현 방식(내부 변수명 등)은 강제하지 않기.
- 테스트는 3~6개로, **FAIL 메시지**는 사용자 행동으로 이어지게 작성.
  - 나쁜 예: "assert failed"
  - 좋은 예: "버튼 클릭 시 숫자가 1 증가해야 해. 클릭 이벤트가 연결됐는지 확인해봐"
- 가능한 한 **첫 FAIL에서 원인 좁히기** (단계별 테스트).

---

## 4) 문장/톤 가이드(초보용)
- 1문장 20자~40자 정도로 짧게.
- "용어 설명"보다 "지금 뭘 하면 되는지"가 먼저.
- 어려운 용어는 괄호로 보조: 예) 이벤트 리스너(클릭 감지)

---

## 5) 미션 검수 체크리스트 (출시 전)
### 기능/흐름
- [ ] 처음 읽었을 때 "뭘 해야 하는지" 30초 안에 이해됨
- [ ] 힌트 없이도 1차 시도 가능
- [ ] 힌트는 1→2→3 단계로 점진적
- [ ] FAIL 메시지가 행동 지침을 줌
- [ ] PASS 후 다음 미션 이동이 자연스럽고 과하지 않음

### 기술/QA
- [ ] 미션 페이지 200
- [ ] Run/테스트 3회 반복해도 동일 결과(비결정성 없음)
- [ ] 새로고침/재접속 후에도 상태가 설명과 일치
- [ ] 모바일 폭에서 UI가 깨지지 않음(최소 확인)

### 난이도/시간
- [ ] 1시간 안에 끝낼 수 있음(초보 기준)
- [ ] 한 번에 새로운 개념은 1개(최대 2개)

---

## 6) 추천 “미션 묶음” 구성(생산용)
- S0(10~15분): 클릭/텍스트 변경/기본 DOM
- S1(15~25분): 조건문/반복/배열 + DOM
- S2(25~45분): fetch/로컬스토리지/폼 검증
- S3(45~60분): 작은 프로젝트(투두/퀴즈/타이머)
